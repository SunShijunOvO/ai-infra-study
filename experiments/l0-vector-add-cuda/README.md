# 最小 CUDA 数组相加

- 状态：已完成（2026-09-18）。本实验范围为固定输入的编译、GPU 计算与结果回传；计时属于后续学习。

## 问题

如何让 CPU 准备的数组经过显存拷贝、GPU Kernel 计算和结果回传，得到正确的逐元素和？

## 实现与分工

用户按分步提示自行编写 Kernel、一维索引与边界、Host 数组、三块显存分配、两次输入拷贝、2×4 线程启动、结果回传与打印。Codex 按用户明确授权补充重复错误检查和清理辅助逻辑，不将这部分记为用户掌握。

[源码](main.cu)以 N=6、A=[1,2,3,4,5,6]、B=[10,20,30,40,50,60] 为输入，每个线程处理一个元素；i=6、7 的线程因 i<N 检查跳过访问。分配失败时清理已成功分配的资源；正常收尾尝试全部释放，保留任何失败。

## 预期与环境

预期 C=[11,22,33,44,55,66]，由导师在实现前给出。

- 实测日期：2026-09-18，Asia/Shanghai。
- Ubuntu 26.04.1，G++ 15.2.0，nvcc 13.4.59，驱动 595.91.07。
- `nvidia-smi --query-gpu=name,compute_cap --format=csv,noheader`：NVIDIA GeForce RTX 5060 Laptop GPU，计算能力 12.0。
- 编译目标显式设为 sm_120。当前沙箱不能访问 GPU，GPU 查询与运行经批准在沙箱外执行。

## 复现

在仓库根目录执行；构建产物位于 Git 忽略的 .tmp：

```bash
mkdir -p .tmp/l0-vector-add-cuda
nvcc -arch=sm_120 experiments/l0-vector-add-cuda/main.cu -o .tmp/l0-vector-add-cuda/main
.tmp/l0-vector-add-cuda/main
```

sm_120 是本机目标，换 GPU 需重新确认计算能力。早期仅用默认目标验证编译与分配，不能据此认定默认目标 Kernel 已在本机运行。

六个元素与预期逐项一致；所有接入的 CUDA 状态检查均成功。当前由 Codex 对输出进行比较，程序尚未自动判断数值正确性。

## 错误检查与同步

- cudaGetLastError 检查启动阶段的错误。
- cudaDeviceSynchronize 等待执行完成并检查执行阶段错误，让初学阶段的错误定位更明确。
- 检查结果回传后才打印；当前默认流中的 Device→Host cudaMemcpy 本身也保证 CPU 在返回后可读取目标结果，因此额外同步主要用于阶段检查。
- 部分分配失败和释放失败路径已审查，未故障注入；没有声称错误路径已实测通过。
