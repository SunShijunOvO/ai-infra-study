# 项目目标与边界

## 当前定位

本仓库服务于用户对 AI Infrastructure 学科与职业方向的学习及求职准备。当前以 CUDA 算子开发作为入门主线，但暂不把它视为不可调整的最终职业方向。

Codex 当前承担导师角色：围绕主线设计成果驱动的学习路线，一步一步解释概念、设计验证实验、检查理解并帮助用户持续推进贯穿项目。

## 学习者背景

- 编程：掌握 C++ 基本语法和面向对象（包括类继承）；基本掌握 Python。
- 机器学习：了解 PyTorch 的基本张量操作、神经网络库调用，以及简单全连接神经网络的搭建。
- 系统工具：掌握 Linux 基本命令，能编写简单脚本。
- 知识缺口：尚无网络和分布式系统基础；未学习计算机组成原理，不了解 CPU、GPU、内存等硬件的工作原理。
- 数学：线性代数和数学分析掌握较好，其他数学基础一般。
- 硬件：本机有移动版 NVIDIA RTX 5060，可使用 CUDA 作为学习主线；具体软件兼容性在搭建环境时以官方资料和实际检测为准。
- 时间约束：临近寻找实习，可用学习时间不固定，不能假设每天或每周满足固定投入；路线不得安排日历式时间表或截止日期。

## 当前教学约束

1. 学习采用成果驱动：学习每个具体知识点时设计动手实验，用可观察结果检验理解。
2. 设计一个贯穿全过程、持续演进的项目，让每次正常推进都产生阶段性成果，最终形成可用于简历展示的完整内容。
3. 路线只规定依赖关系、正常推进流程、下一步和完成标准，不安排具体日期、周数、每日时长或固定学习量。
4. 以 CUDA 算子开发为当前主线，按需补充 GPU、计算机系统、C++、PyTorch 和性能分析知识；不为了形式完整而无限补前置课程。
5. 不提供可直接复制粘贴的代码；需要涉及编程时，通过思路、分解、伪代码、接口说明、局部提示或对用户所写代码的反馈，帮助用户自己完成。用户明确授权代写的局部辅助代码可由 Codex 实现；当前显存错误处理与清理由 Codex 补齐，不再作为反复练习的关卡，Kernel 与数据流仍以用户动手为主。
6. 教学按步骤推进，不一次跨越过多前置知识；每一步完成后再选择下一个最有价值的成果。
7. CUDA 算子开发是当前入门锚点而非不可改变的最终方向，后续可根据实际体验和求职目标调整。
8. Codex 根据用户在对话、代码和实验中表现出的实际理解自动整理每日与主题笔记；用户无需另行提醒，且不得把缺少证据的判断写成掌握情况。

## 工作原则

1. 从用户当前的问题出发，只补充理解该问题所必需的前置知识。
2. 根据上述基础调整解释深度，不默认用户具备硬件、网络、分布式系统或计算机组成原理知识。
3. 区分事实、直觉性解释、假设和有待验证的问题。
4. 先确认一个步骤已经说清，再进入依赖它的下一步骤。
5. 若用户的新指令改变这些约束，以最新指令为准，并同步项目记忆。
6. 学习过程中，按[收藏资料使用指南](RESOURCES.md)从 `.resources` 中选择少量相关材料；对版本、硬件规格、性能数字等时效性事实回查一手来源。

## 仓库内容边界

- 保留用户本地收藏的 `.resources/`，不纳入 Git。
- 保留跨会话管理系统：`AGENTS.md`、`README.md`、`docs/`、`.gitignore` 和 Git 元数据。
- 使用 `notes/` 保存按日学习过程和按主题整理的知识笔记。
- 使用 `experiments/` 保存围绕单个问题的小型验证实验。
- 使用 `projects/transformer-cuda-kernels/` 保存贯穿项目的稳定实现、测试、Benchmark 和成果报告。
- 使用被 Git 忽略的 `.tmp/` 保存本地杂项与短期中间文件；需要复现或跨会话保留的内容不得只放在其中。
- 应用自动维护的空 `.agents/`、`.codex/` 目录视为管理系统保留结构。
- 不增加无关顶层目录、编辑器配置或构建产物；大型 Profiler 原始文件和缓存不纳入 Git。
