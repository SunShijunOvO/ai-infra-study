# CUDA 算子开发学习路线与规划

- 状态：已确认
- 最后更新：2026-09-17
- 结论摘要：学习按 L0—L7 的知识依赖推进，以 CUDA C++ 为主线，围绕当前项目按需补 C++、计算机系统、数值计算和 PyTorch 基础。路线不设置日期或学习时长；只有达到阶段掌握标准后才继续。

## 路线目标

完成主线后，学习者应具备以下入门能力：

1. 能从数学定义和张量布局设计一个基础 CUDA 算子的并行映射。
2. 能独立实现、测试和调试中等难度的 CUDA Kernel。
3. 能判断算子主要受计算、访存、同步、资源或启动开销中的哪一类因素限制。
4. 能通过规范 Benchmark 和 Profiling 验证性能假设，而非盲目调参。
5. 能处理基本数值稳定性、边界形状、数据类型和误差问题。
6. 能将已验证的 CUDA Kernel 接入 PyTorch，并说明框架调用带来的额外约束。
7. 能完整讲述一个算子从基线、错误、分析到多轮优化的过程和适用边界。

这是一条“具备独立学习和继续深入能力”的入门路线，不以掌握所有 CUDA 特性、追平厂商库或覆盖所有算子为目标。


## L0：开发闭环与最小系统基础

### 核心问题

CUDA 程序怎样从 C++ 源文件变成在 GPU 上执行的 Kernel？数据、控制流、错误和时间分别发生在哪里？

### 必学内容

- C++ 源文件、头文件、编译、链接与库的最小概念；
- 指针、数组、连续内存、对象生命周期和基本 RAII；
- CPU 与 GPU 的职责，Host 与 Device 地址空间；
- CUDA 内存分配、拷贝、Kernel 启动和释放；
- 异步执行、显式同步和错误检查；
- CPU 计时与 CUDA Event 计时的差异；
- Linux 下最小构建、运行和故障定位流程。

### 按需补充，不独立扩张

- CMake 或其他构建工具只学项目实际使用的部分；
- C++ 模板只要求能读懂简单泛型接口；
- 不在此阶段系统学习现代 C++ 全部特性、操作系统课程或汇编。

### 掌握标准

- 能画出一次 Kernel 调用涉及的 CPU、GPU 和数据路径；
- 能解释为什么不恰当的 CPU 计时会得到错误结果；
- 能独立定位编译错误、链接错误和 CUDA 运行时错误属于哪一层；
- 能写出资源释放和错误检查完整的最小程序结构。

### 对应项目出口

[项目路线 M0](cuda-operator-roadmap.md#m0可复现的-cuda-项目骨架)。

## L1：CUDA 执行模型

### 核心问题

大量 GPU 线程如何被组织，怎样把张量元素分配给线程？

### 必学内容

- Kernel 和 Kernel Launch；
- Grid、Block、Thread 及内置索引；
- 一维、二维和扁平化索引；
- 边界判断和 Grid-Stride Loop；
- Warp 与 SIMT 的基本直觉；
- 分支发散及其适用边界；
- Block 大小、线程数量和工作粒度的基本关系。

### 暂缓内容

- 具体 GPU 架构代际的全部 SM 细节；
- Warp Specialization、持久化 Kernel 等高级调度方式；
- PTX/SASS 深入分析。

### 掌握标准

- 面对一维或二维输入，能在写代码前给出线程映射公式；
- 能证明线程覆盖了全部合法元素且没有越界；
- 能解释 Warp 内分支何时可能影响效率；
- 能根据问题选择基本的线程粒度，而不是机械使用固定 Block 大小。

### 对应项目出口

[项目路线 M1.1—M1.2](cuda-operator-roadmap.md#m1gpu-编程模型与数据映射)。

## L2：CUDA 内存模型与数据布局

### 核心问题

为什么运算量相同的两个 Kernel 会因为访问方式不同而产生明显性能差异？

### 必学内容

- 寄存器、Shared Memory、Global Memory 和 Cache 的职责；
- 延迟、带宽、吞吐量和容量的区别；
- 张量连续性、Stride、行主序及索引计算；
- 合并访存的基本条件；
- 数据复用与 Shared Memory 的使用动机；
- Bank Conflict 的基本现象；
- AoS/SoA 等布局思想只在实验需要时引入。

### 暂缓内容

- 所有 Cache 控制策略和底层指令；
- Unified Memory 深度优化；
- 异步拷贝、多级流水线和架构专属内存特性。

### 掌握标准

- 能根据索引表达式推断相邻线程访问的地址关系；
- 能区分“数据没有复用”和“数据有复用但没有被利用”；
- 能通过控制变量实验验证连续与跨步访问的差异；
- 能说明何时使用 Shared Memory 可能得不偿失。

### 对应项目出口

[项目路线 M1.3](cuda-operator-roadmap.md#m1gpu-编程模型与数据映射)。

## L3：并行协作与归约

### 核心问题

当一个输出需要多个线程共同计算时，怎样正确而高效地交换和合并数据？

### 必学内容

- 数据依赖、Race Condition 和同步；
- Block 内同步的语义与限制；
- 原子操作的用途和代价；
- Shared Memory 树形归约；
- Warp Shuffle 和 Warp 级协作；
- Block 内、Block 间与多 Kernel 分层归约；
- 非二次幂长度、不规则形状和数值误差。

### 暂缓内容

- Cooperative Groups 的完整 API；
- Scan、Histogram 等所有并行原语；
- 跨 GPU 同步与集合通信。

### 掌握标准

- 能指出一个并行程序中潜在的数据竞争；
- 能解释每个同步点保护的依赖关系；
- 能从朴素 Reduction 推导到 Shared Memory 和 Warp 版本；
- 能比较不同实现的同步、访存和并行度成本。

### 对应项目出口

[项目路线 M2](cuda-operator-roadmap.md#m2并行归约原语)。

## L4：数值计算与 Transformer 基础算子

### 核心问题

怎样把并行原语组合成真实算子，并同时保证数值正确性、边界正确性和实现效率？

### 必学内容

- 浮点表示、舍入误差、溢出和下溢的基本直觉；
- 绝对误差、相对误差及合理容差；
- Softmax 的数学定义和数值稳定变换；
- 均值、方差、RMSNorm 与 LayerNorm 的计算结构；
- FP32、FP16、BF16 的用途与累加精度概念；
- Kernel Fusion 的收益来源和限制；
- Batch、行宽、隐藏维度等形状怎样改变并行方案。

### 暂缓内容

- 完整 Transformer 理论和模型训练；
- 混合精度训练系统；
- FlashAttention 推导与完整实现；
- 量化算子的系统学习。

### 掌握标准

- 能从数学定义拆解算子的逐元素、归约和归一化步骤；
- 能解释稳定 Softmax 为什么需要减去最大值；
- 能为不同数据类型定义有依据的正确性容差；
- 能判断两个操作是否具有值得尝试的融合机会。

### 对应项目出口

[项目路线 M3](cuda-operator-roadmap.md#m3transformer-基础算子)。

## L5：CUDA 性能工程

### 核心问题

一个正确 Kernel 为什么慢，怎样用证据找到限制因素并验证优化？

### 必学内容

- 延迟、吞吐量、带宽、FLOPS 与利用率；
- 预热、重复测量、同步、统计汇总和输入矩阵设计；
- Kernel 时间、数据传输、框架开销与端到端时间；
- 算术强度与 Roofline 的基本分析方式；
- Memory-bound、Compute-bound、Latency-bound 的区别；
- Occupancy、寄存器、Shared Memory 和线程块之间的资源约束；
- Nsight Systems 用于时间线，Nsight Compute 用于 Kernel 指标；
- 假设—实验—指标—结论式优化方法；
- 性能可移植性与输入形状边界。

### 深度边界

这一阶段要求能够正确使用工具和解释关键指标，但不要求记忆所有指标、阅读全部 SASS 或对某一代 GPU 做极限榨取。

### 掌握标准

- 能识别不可靠 Benchmark 的常见问题；
- 能先提出瓶颈假设，再选择对应指标；
- 能把 Profiling 结果转化为具体且可证伪的修改方向；
- 能解释优化收益、退化区间以及结论是否可推广。

### 对应项目出口

[项目路线 M4](cuda-operator-roadmap.md#m4系统化性能工程)。

## L6：PyTorch 自定义算子工程

### 核心问题

怎样让独立 CUDA Kernel 成为框架中正确、可用、可测试的算子？

### 必学内容

- PyTorch Tensor 的 Shape、Stride、Dtype、Device 与 Contiguous；
- Python、C++、CUDA 之间的调用和构建边界；
- 自定义算子注册与基本 Dispatch 概念；
- 参数、设备、类型、形状和连续性检查；
- 框架级正确性与集成测试；
- 框架调用开销与独立 Kernel Benchmark 的差异；
- Autograd 只在选择的算子和项目展示确有需要时加入。

### 暂缓内容

- PyTorch Dispatcher 全部内部实现；
- torch.compile、Inductor 与完整编译栈；
- 多设备、多后端和分布式集成。

### 掌握标准

- 能说明一次 Python 调用如何到达自己的 CUDA Kernel；
- 能对非法输入给出明确失败，而不是产生未定义行为；
- 能区分 Kernel 正确性测试和框架集成测试；
- 能解释框架测得的时间为什么可能高于独立 Kernel 时间。

### 对应项目出口

[项目路线 M5](cuda-operator-roadmap.md#m5pytorch-自定义算子接入)。

## L7：综合复盘与求职准备

### 核心问题

能否脱离教程分析一个新问题，并把自己的设计、证据和局限讲清楚？

### 必学内容

- 从算子定义、数据布局和目标硬件推导并行方案；
- 阅读陌生 Kernel 的数据流、同步和资源使用；
- 调试错误结果、非法访问和性能异常；
- 复现实验、审查指标口径和识别夸大结论；
- 用问题、基线、瓶颈、方案、证据和边界组织项目陈述；
- 针对 CUDA、GPU、并行归约、性能分析和 PyTorch 接入准备追问。

### 掌握标准

- 能为一个未做过的基础算子给出合理的初版映射和验证方案；
- 能审查一段 Kernel 并指出至少正确性、访存和同步三个方面的风险；
- 能根据项目原始结果回答性能数字的环境、输入和口径；
- 能坦诚解释失败优化、当前限制和下一步，而非只背结论。

### 对应项目出口

[项目路线 M6](cuda-operator-roadmap.md#m6项目收口与求职表达)。

## 按需补基础的触发规则

前置知识不单独排成长课程。出现下列阻塞时，进入一个最小补课支线，解决后立即回到主线：

| 触发现象 | 补充内容 | 停止条件 |
|---|---|---|
| 看不懂指针、生命周期或链接错误 | C++ 内存、RAII、编译与链接 | 能解释并修复当前问题 |
| 无法理解 Cache、带宽或数据搬运 | 计算机组成中的内存层次 | 能画出当前 Kernel 的数据路径 |
| 无法判断竞争或同步 | 并发、依赖和临界区直觉 | 能指出当前依赖和同步位置 |
| Softmax/Norm 误差无法解释 | 浮点、误差和数值稳定性 | 能设计误差测试并解释结果 |
| PyTorch 输入行为不明确 | Tensor 布局、Dtype、Device | 能定义并验证接口契约 |
| 工具指标看不懂 | 只补当前假设相关的硬件与指标 | 能用该指标证实或否定假设 |

禁止因为遇到一个术语就无限向前追溯。补课的出口永远是重新解决主线中的具体问题。

## 单个知识点的学习规范

每个知识点采用同一套成果驱动流程：

1. **提出问题**：它解释当前项目中的什么现象？
2. **建立模型**：用自己的话描述机制和关键变量。
3. **做出预测**：改变一个变量后，正确性或性能应如何变化？
4. **设计实验**：保留基线，一次只改变一个主要因素。
5. **观察证据**：记录环境、输入、结果和异常。
6. **解释结果**：区分证实、否定和无法判断。
7. **迁移应用**：把结论用于项目 Kernel、测试、工具或设计。
8. **口头复述**：不看资料回答机制、权衡和适用边界。

一个知识点只有同时产生“自己的解释、实验结果、项目应用”才算完成。阅读、抄写和成功运行示例仅是中间步骤。

## 推进与回退规则

- 不按日期前进，只按掌握标准前进。
- 一个阶段可有少量未解决问题，但不得缺失其核心正确性基础。
- 如果新阶段暴露旧阶段理解错误，立即回退到对应节点补实验，不把错误基础继续向后传播。
- 性能结论必须先保证正确性；框架接入必须先保证独立 Kernel 正确；高级优化必须先有可信基线。
- 每完成一个阶段，做一次阶段复盘：能解释什么、能独立完成什么、证据在哪里、还不能做什么。

## 知识优先级

### P0：主线必须掌握

- CUDA 执行与内存模型；
- 线程映射、边界和数据布局；
- 同步、归约和 Warp 协作；
- 正确性、数值稳定性和误差测试；
- Benchmark、Profiling 和瓶颈分析；
- PyTorch 自定义算子的基本接入。

### P1：按项目需要掌握

- 半精度与向量化访问；
- 原子操作；
- Occupancy 的定量分析；
- Kernel Fusion；
- 简单模板与泛型；
- Autograd 或 Triton 对照实现。

### P2：首轮暂缓

- Tensor Core 和手写高性能 GEMM；
- PTX/SASS 深度调优；
- CUTLASS；
- FlashAttention 完整实现；
- AI 编译器、分布式训练和推理引擎；
- 架构专属极限优化与多硬件后端。

## 资料策略

每个学习节点通常只使用三类材料：

1. 一份官方资料确认语义、接口和时效性事实；
2. 一份本地概念资料帮助建立直觉；
3. 当前实验和项目代码作为最终验证。

本地优先使用 `AIInfraGuide` 的 CUDA 编程模型、内存模型、Reduce、Softmax 和性能工具文章；用 `ai_infra` 定位主题及补充求职表达。进入具体节点时再核对 NVIDIA CUDA 文档、Nsight 文档和 PyTorch 官方自定义算子文档，不提前囤积材料。
