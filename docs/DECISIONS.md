# 关键决策记录

本文件记录会影响未来工作的选择。条目按时间倒序排列；旧决策被替代时保留原文，并在状态和“后续”中链接新决策。

## D-002：探索期采用导师式按需答疑

- 日期：2026-09-16
- 状态：已采纳
- 背景：用户的暂定目标是求职，但仍在探索 AI Infrastructure 学科及未来职业方向；当前基础覆盖基本编程、少量 PyTorch 和 Linux，而网络、分布式系统、计算机组成及硬件原理尚未学习。
- 决定：当前由用户的问题驱动学习，Codex 作为导师逐步讲解；暂停制定学习计划、设计实验和项目；不提供可直接复制粘贴的代码，而是帮助用户理解并自行写出。
- 理由：用户明确要求保留探索空间，并希望通过循序渐进的答疑建立理解，而不是过早固定路线或代写代码。
- 影响：后续会话不得把路线图占位内容当作待执行计划；普通提问不授权主动安排课程、实验或项目。回答涉及编程时应使用思路、拆解、伪代码、局部提示或针对用户代码的反馈。
- 后续：只有用户明确提出新要求时才恢复规划、实验或项目设计；届时以新决策补充或替代本条。

## D-001：使用仓库内 Markdown 作为跨会话记忆层

- 日期：2026-09-15
- 状态：已采纳
- 背景：项目需要让新的 Codex 会话快速恢复上下文，且记忆应与代码一起版本化、可审阅、可搜索。
- 决定：采用 `AGENTS.md` 作为自动入口，并将稳定目标、当前状态、路线图、决策、会话记录和主题笔记分别保存在仓库内的 Markdown 文件中。
- 理由：纯文本不依赖外部服务，适合 Git 审阅；按信息生命周期拆分可减少单个“记忆文件”不断膨胀和相互矛盾。
- 影响：每次实质工作结束时需要检查 `CURRENT.md`；只有里程碑、决策或重要上下文变化时才更新对应文档。
- 后续：若文档规模明显增长，再评估按 ADR 文件或阶段归档；当前不提前增加复杂度。

## 新决策模板

复制以下模板到文件顶部，并将 `NNN` 替换为递增编号：

```markdown
## D-NNN：简短标题

- 日期：YYYY-MM-DD
- 状态：提议 / 已采纳 / 已替代 / 已拒绝
- 背景：要解决的问题和约束。
- 决定：选择了什么。
- 理由：为什么这样选，以及主要替代方案。
- 影响：对后续实现、学习或维护的约束。
- 后续：验证点，或替代本决策的新条目链接。
```
