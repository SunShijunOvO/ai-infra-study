# AI Infra 收藏资料使用指南

- 状态：已验证
- 最后更新：2026-09-16
- 结论摘要：`.resources` 应作为按问题取用的分层资料库，而不是从头到尾完成的课程。`ai_infra` 用来建立全景和定位主题，`AIInfraGuide` 用来补充具体概念，`cann-learning-hub` 只在明确探索昇腾/CANN 时作为专项实践库；外部网站主要承担补充讲解、练习和生态入口的角色。

## 目的与边界

这份指南规定学习 AI Infra 时如何利用本地收藏资料。它是资料导航和取用方法，不是学习计划；当前已经选择 CUDA 算子开发作为入门主线，具体知识顺序以[CUDA 学习规划](cuda-learning-plan.md)为准。

本地收藏位于 `.resources/`，当前被 `.gitignore` 排除，不随本仓库版本化。本文记录的是资料角色和相对路径；如果本地收藏被移动、删除或重新拉取，需要重新核对。

## 各资料的正确用法

### `ai_infra`：先确定问题位于哪里

把它当作 AI Infra 的目录和术语地图，而不是必须按 01 到 17 依次完成的课程。

当前优先入口：

- `01_全景认知与前置基础/1.1_什么是AI_Infra/1.1_什么是AI_Infra.md`
- `01_全景认知与前置基础/1.2_大厂AI_Infra组织架构/1.2_大厂AI_Infra组织架构.md`
- `01_全景认知与前置基础/1.3_AI_Infra岗位路线图/1.3_AI_Infra岗位路线图.md`

其余章节只在出现相关问题时打开。例如，先通过第 5 章确认 PagedAttention 属于 LLM 推理与 Serving，再去更细的资料理解机制，而不是顺带把第 5 章全部学完。

### `AIInfraGuide`：回答“它为什么这样工作”

它的覆盖面比 `ai_infra` 集中，但 GPU、CUDA、Transformer、集合通信等基础主题拆解得更细，适合在已经确定问题后精读一篇文章。

对当前学习者尤其有价值的入口：

- `docs/guides/模块一-前置知识/gpu/gpu-basics.md`
- `docs/guides/模块一-前置知识/transformer/Transformer架构快速入门.md`
- `docs/guides/模块一-前置知识/communication/collective-communication-primer.md`
- `docs/guides/模块二-CUDA编程与算子优化/CUDA编程入门指南.md`

总章用于预览知识结构；细分文章用于解决当前问题。不同时通读总章和全部子文章。

### `cann-learning-hub`：明确选择昇腾方向后再进入

这个仓库以可运行课程和工程实践为核心，包含大量 Notebook、Python、C++、课件和图片。适合用于：

- 认识昇腾 NPU 和 CANN 软件栈；
- 在 CANNLab 或昇腾环境中运行推理、训练和 Profiling；
- 学习 Ascend C 自定义算子；
- 比较 CUDA 与 CANN 的开发和优化方式。

它明确假设读者具备计算机组成原理、操作系统、进程/线程和内存管理等基础，而当前学习者尚未具备这些前置知识。因此，在没有明确的昇腾兴趣和可用环境前，不把它作为通用入门教材，也不进入算子开发和训练流水线。

仓库使用专门的 CANN Open Software License；以后复用、修改或分发其中代码前，应先检查其 `LICENSE`，不能默认与普通宽松开源许可证相同。

### 外部网站：承担补充而非主线

- AIInfraGuide 在线站：本地仓库的网页阅读入口，适合日常浏览；本地副本适合全文搜索和比较。
- 杜子源的博士居：CUDA、Triton、LeetGPU 习题和从零实现 vLLM 等个人系列，适合观察实现思路，不作为唯一权威来源。
- LeetGPU：适合在理解 Grid、Block、Thread、内存访问和同步后做题；不用于第一次学习概念。
- CANN：只在探索昇腾生态时作为官方入口。

网站清单见 `.resources/websites/ai-infra-study-websites.md`。网站内容会变化，使用时需要重新检查。

## 每次学习问题的取用流程

### 1. 把主题改写成具体问题

好的问题示例：

- PagedAttention 为什么能减少 KV Cache 的内存浪费？
- 为什么 Ring AllReduce 的通信量与参数规模有关？
- GPU 的 Shared Memory 为什么可能提高 Kernel 性能？

过于宽泛的问题示例：“学习 LLM 推理”“学完 CUDA”。宽泛主题应先拆成一个当前能够回答的问题。

### 2. 用地图确定位置和前置依赖

先在 `ai_infra` 中找到所属方向，确认当前问题主要涉及：

- 计算；
- 通信；
- 显存容量或带宽；
- 调度与工程可靠性。

同时识别理解它所必需的最小前置知识。缺少前置时只补当前问题需要的一层，不无限向前追溯。

### 3. 选择一到三份材料

默认组合为：

1. 一份 `ai_infra` 概览用于定位；
2. 一份 `AIInfraGuide` 细分文章用于理解；
3. 必要时增加官方文档、代码或练习用于验证。

不要为了“完整”同时打开大量重复文章。两份资料说法不同时，记录差异并寻找原始论文、官方文档或可复现实验。

### 4. 形成自己的答案

每学一个机制，至少能够回答：

1. 它解决什么具体问题？
2. 没有它时瓶颈在哪里？
3. 它改变了计算、通信或显存中的哪一项？
4. 它牺牲了什么，换取了什么？
5. 它在什么条件下不适用？

如果只能复述名词和结论，说明还没有真正理解。

### 5. 最后再读代码或做练习

先预测代码的数据流、资源使用和可能瓶颈，再阅读或运行代码。练习用于检验理解，不以“成功运行”代替机制解释。

当前采用成果驱动路线：每个知识点应通过 `experiments/` 中的小型实验验证，并将稳定成果整理到贯穿项目；仍不直接代写可复制粘贴的完整代码。

### 6. 核验时效性事实

以下信息不能只依赖收藏资料：

- GPU/NPU 型号、显存、带宽和峰值算力；
- 框架 API、安装方式和版本兼容性；
- 云服务或硬件价格；
- 最新论文、项目状态和行业岗位信息；
- 性能数字和 Benchmark 结论。

使用时优先回查官方文档、论文和项目仓库，并记录硬件、软件版本、参数和访问日期。

## 给后续 Codex 会话的使用规则

处理用户提出的 AI Infra 学习问题时：

1. 先根据本指南在 `.resources` 中检索相关材料，通常只选一到三份。
2. 告诉用户所选材料各自解决什么问题，而不是仅给出文件列表。
3. 根据 `docs/PROJECT.md` 中记录的学习者背景补充必要前置知识，不假定其具备硬件、网络、分布式或计算机组成基础。
4. 把资料中的说法分成稳定机制、版本相关事实和有待核验的结论；对后两者使用一手来源验证。
5. 保持问题驱动和逐步讲解，不把资料目录自动转换成固定学习路线。
6. 一个主题形成可复用理解后，再考虑在 `docs/` 新建或更新相应学习文档，并登记到 `docs/README.md`。
