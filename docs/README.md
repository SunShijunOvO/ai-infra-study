# 项目文档索引与写作规范

`docs/` 保存项目记忆、稳定规划和跨会话管理文档。学习过程、知识点、重难点和踩坑写入 `notes/`，小型验证写入 `experiments/`，稳定代码与性能成果写入 `projects/`。

## 固定文档

| 文件 | 回答的问题 | 更新频率 |
|---|---|---|
| [PROJECT.md](PROJECT.md) | 为什么做、做什么、不做什么？ | 方向或稳定原则变化时 |
| [CURRENT.md](CURRENT.md) | 现在在哪里、接下来做什么、卡在哪里？ | 每次实质工作后检查 |
| [ROADMAP.md](ROADMAP.md) | 计划按什么阶段推进？ | 学习或项目里程碑变化时 |
| [DECISIONS.md](DECISIONS.md) | 为什么选择当前方案？ | 关键决策产生时 |
| [SESSIONS.md](SESSIONS.md) | 上一次重要工作留下了什么上下文？ | 重要会话结束时 |
| [RESOURCES.md](RESOURCES.md) | `.resources` 中的资料如何分工和取用？ | 收藏结构或使用方法变化时 |

`CURRENT.md` 是短期状态的唯一事实来源，其他文件不要再维护另一份“当前待办”。

## 文件命名约定

- 早期建立的固定管理文档使用大写文件名：`PROJECT.md`、`CURRENT.md`、`ROADMAP.md`、`DECISIONS.md`、`SESSIONS.md`、`RESOURCES.md`。
- 后续新增的专题规划文档使用小写连字符命名，例如 `cuda-learning-plan.md`。

这种差异来自文档创建阶段不同，是历史约定而非技术要求；当前通过固定文档与专题文档的职责差异保持可预测性。若未来统一命名，应一次性重命名并更新全部链接，避免只改部分文件。

## 稳定规划文档

跨会话必须遵守的稳定路线、方法和资源指南放在 `docs/`。具体知识主题不再放入这里，而是写入 `notes/topics/`。

## 写作要求

- 一个文件聚焦一个清晰问题或主题。
- 开头写一句“结论摘要”，让读者快速判断是否相关。
- 区分来源事实、自己的推导、实验观察和未验证假设。
- 优先链接仓库内实验；外部资料记录标题、URL 和访问日期。
- 有数值结论时记录硬件、软件版本、参数和复现命令。
- 内容过时后标记状态并链接替代文档，不直接抹去有价值的历史。
