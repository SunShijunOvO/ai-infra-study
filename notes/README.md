# 学习笔记

`notes/` 保存学习者在 CUDA 算子开发过程中的个人知识记录，与 `docs/` 中的项目管理、路线和决策文档分开。

## 目录

```text
notes/
├── daily/     # 按日记录学习过程、实验链接、问题和下一步
└── topics/    # 按主题整理经过消化的稳定理解
```

## 使用原则

- 笔记由 Codex 在每次有实质学习推进后自动整理，用户不需要另行要求或手工维护。
- Codex 只根据对话回答、用户实际编写的内容、实验结果和明确修正记录学习表现；不得凭印象推断用户已经掌握或没有掌握某项知识。
- `daily/` 回答“今天推进了什么、看到了什么现象、还卡在哪里”。文件名使用 `YYYY-MM-DD.md`；同一天只维护一个文件。
- `topics/` 回答“这个机制是什么、为什么、证据和边界是什么”。文件名使用小写连字符，例如 `cuda-thread-hierarchy.md`。
- 日记中的知识结论成熟后整理到主题笔记，日记只保留摘要并链接过去，不复制整段正文。
- 主题笔记优先链接对应实验和项目代码；性能数字必须记录环境、输入、口径和结果位置。
- 临时猜测明确标记为“待验证”，不能写成已经确认的事实。
- `docs/CURRENT.md` 仍是项目当前状态的唯一来源；笔记不维护另一份全局待办。

## 自动整理规则

每次实质学习结束时，Codex 自动执行：

1. 更新当日 `daily/YYYY-MM-DD.md`，记录本次目标、用户表现出的理解、实验或代码证据、踩坑、修正和尚未解决的问题。
2. 只在一个知识点已经形成可复用理解时，新建或更新 `topics/<topic>.md`；尚未验证的认识只留在日记并标记状态。
3. 将实验链接到 `experiments/`，将稳定应用链接到 `projects/`，不在笔记中复制代码或大段原始输出。
4. 区分“用户已经独立完成”“在提示后完成”“仍需验证”，避免把导师给出的解释记成用户已经掌握。
5. 清理已失效的下一步和重复内容，但保留有价值的错误、修正过程和结论边界。

## 日记建议结构

```markdown
# YYYY-MM-DD

## 本次目标

## 学到的内容

## 动手与证据

## 踩坑与修正

## 尚未解决

## 下一步
```

## 主题笔记建议结构

```markdown
# 主题名称

- 状态：草稿 / 已验证 / 待修正
- 最后更新：YYYY-MM-DD
- 结论摘要：一到三句话。

## 要回答的问题

## 心智模型

## 实验或项目证据

## 常见错误与踩坑

## 适用边界

## 未解决问题

## 资料
```
